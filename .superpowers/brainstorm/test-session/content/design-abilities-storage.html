技能系统 & 存储层设计

Ability 系统架构

出发点是 F 不自创脚本语言 — 所以技能效果通过预定义类型 + 配置参数实现

abilities: 配置即逻辑
# 玩家无需写代码，只需选效果类型+填参数
abilities:
# 主动技能 — 右键触发
right_click:
type: lightning_strike # 预定义效果类型
cooldown: 10 # 秒
mana_cost: 20
damage: 8
# 被动效果 — 穿戴时生效
on_wear:
type: potion_effect
effect: speed
amplifier: 1

预定义效果类型举例：lightning_strike, potion_effect, projectile, explosion, heal, teleport, summon, particle_ring

将来 Phase 3 脚本引擎接入后，可以加 script: my_script.js 扩展任意逻辑

SQLite 存储结构

-- 运行时状态 / 玩家数据
CREATE TABLE player_cooldowns (
player_uuid TEXT PRIMARY KEY,
item_id TEXT,
ability_key TEXT,
expires_at INTEGER
);

CREATE TABLE player_data (
player_uuid TEXT PRIMARY KEY,
unlocked_items TEXT -- JSON array: ["demo_sword", ...]
);

-- 注意: 物品定义本身在 YAML 中，SQLite 只存运行时状态

数据流总结

# 写入路径
GUI 编辑 → YamlWriter → items/*.yml

# 读取路径
YamlWatcher → ItemDefinition → AssetRegistry → ItemManager → 游戏

# 运行时状态
玩家冷却/数据 → SQLite (item 定义不同步到 SQLite)
