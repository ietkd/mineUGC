Phase 1 架构方案对比

Core Framework + 自定义物品

方案 A：分层模块架构 ⭐ 推荐

mineUGC 模块分层
mineUGC/
├── mineUGC-core — 接口、注册表、事件系统、热加载引擎
├── mineUGC-items — 自定义物品系统（属性、技能、套装）
├── mineUGC-storage — YAML 读写 + SQLite 运行时存储
└── mineUGC-gui — 游戏内编辑 GUI

优点

  • 职责清晰，每个模块独立可测试
  • 未来加方块/ NPC 只需加新模块
  • 热加载只影响相关模块

缺点

  • 初期搭建稍复杂
  • 模块间需要定义好 API

方案 B：单体插件

所有代码在一个 Gradle 模块里，按 package 分包

优点

  • 开发速度快，简单直接

缺点

  • 随着功能增加会变得庞大
  • 测试难度高
  • 未来拆分会很难

方案 C：Core API + 独立实现插件

core 作为 API JAR，各功能作为独立插件加载

优点

  • 最强的隔离性
  • 可单独装卸功能

缺点

  • 过度设计，对当前阶段太重
  • 多 JAR 部署繁琐
